# 新训练噪声策略的独立零LLM顺序预测协议

本协议在新一轮测量之前冻结；不得利用已知旧留出点反复选择策略。计划编号 `gp-noise-validation-001`，本次文档提交时尚未执行。

## 固定条件

- 复用三个固定配置：Default（1 GiB/并发0）、BufferOnly（4 GiB/并发0）、Concurrency8（4 GiB/并发8）；其余参数均为io_capacity=200、max=2000、排序缓冲256 KiB。
- 顺序D/B/C、B/C/D、C/D/B，共9次。MySQL 8.0.36、四表各200万行、32线程、uniform、种子42、预热15秒+正式60秒，不限请求速率。
- 同一初始快照冷恢复一次，每次恢复共同配置和并发上下文。不修改OS参数或持久性，不清理历史数据，不因异常自动补跑。
- 最多9次测量，0次API/0 tokens；执行器1500秒提交截止，并保留最终恢复与核验。预计12～15分钟，不声称抢占式硬墙钟上限。
- 原71次运行仅用于冻结配置来源校验，不导入它的纯TPS训练数据；旧综合闭环和重复实验观测也不导入新模型。

## 两种策略与顺序检验

1. 前6次为共同启动数据，目标为同次TPS/P95保留6位小数后取自然对数，完整配置编码及常量上下文相同。
2. Legacy：复现现有控制器的GP更新方式，首次拟合优化，之后每10模型版本重优化，其余仅重新拟合；固定噪声项为0。
3. RepeatAware：按冻结的 `repeat_aware_gp_v1` 分组估计训练噪声，至少3个重复自由度启用固定项，每批新增有效观测都重新优化超参数。
4. 7号预测只使用1～6号；8号只使用1～7号；9号只使用1～8号。预测和训练快照必须在对应真实测量前封存，禁止覆盖或回填。
5. 两版模型在每一步使用相同的过去观测，不改变预定配置。记录±2倍观测标准差区间，同时保留潜在标准差；不宣称这是安全保证。

这属于**顺序预测检验**，不是上一轮固定6/3留出。已完成的7号允许训练8号，但7号自身预测必须保持原样；不能把三个检验点说成始终未进入任何后续训练集。

## 报告要求

- 完整原生压测日志、TPS/P95、规范目标、实际配置、CPU/节流边界及最终恢复审计。
- 三个测量前提交文件，包括时间、过去训练编号、两版快照和预测；任何训练编号均须小于被预测编号。
- 每个点的误差、区间覆盖、宽度，以及训练噪声估计/自由度、固定项、残余项、总噪声和优化记录。
- 两种策略只比较三个顺序预测点，全部保留；不得根据结果再增删点、调噪声倍数或换最好种子。
- 不论结果如何，都不能由三点证明总体覆盖率、ADMTune搜索增益或优于其他调优方法。
- 若失败，保留失败和恢复情况，不重新开账本掩盖。

## 运行入口

必须先完成独立冷恢复和专用实例预检，再使用新输出目录：

```sh
python -m admtune.static_diagnostic \
  --target configs/local/workset-v2-target.yaml \
  --benchmark configs/local/timed-readonly-100min.yaml \
  --knobs configs/local/concurrency-knobs.yaml \
  --output runs/gp-noise-validation-001 \
  --restore-audit runs/gp-noise-restore-001/restore.json \
  --parent-run /root/PaperTest100/runs/timed-static-100min-002 \
  --dedicated-instance --concurrency-probe --repeat-aware-audit
```

不需要 `--allow-paid-llm`，不应启动任何LLM客户端请求。该入口也不等于已切换完整付费ADMTune控制器。
