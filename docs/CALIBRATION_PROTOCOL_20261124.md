# 零模型校准协议（2026-11-24）

## 目的与边界

先检查现有轻量负载是否对参数敏感、同配置波动是否足以掩盖收益，再决定正式实验规模。本入口不实例化模型客户端，不训练 GP，不进行自适应参数搜索，不更改操作系统或持久性设置。

仅用于专用本地 MySQL 8.0.36，复用现有四张 Sysbench 表和单 SQL 请求协议；不是 Sysbench 事务 TPS，不是正式基线或消融。UPDATE 会修改数据；本轮不做数据快照复位、不清缓存、不重启 MySQL。

## 固定测量协议

- 每个请求流 84 秒；前 15 秒预热，按计划到达时刻截取 `[15,75)` 的 60 秒请求 cohort；剩余 9 秒维持同一流并排空。
- 保持四个工作线程、有界队列、每个请求超时和现有回放的十万请求上限；不为高到达率另行放宽安全限制。
- 单条主键 SELECT/UPDATE，autocommit。A 固定 90% 读，B 固定 10% 读，均每秒严格保持组成；不在一次测量中切换组成。
- 单次 steady 回放内部的阶段标签恒定；A/B 组成以试验 `read_percent` 和真实 operation 列区分，不能根据内部固定阶段标签推断读写比例。
- 与此前动态目标一致，P95 按请求发出到完成计算；另外保存计划发出滞后、排队和服务时间，区分客户端调度/排队限制与数据库压力。
- 完整性、失败、配置代际、会话参数读回不符等均使性能标签无效。过载原始记录保留，不当作成功性能样本。

## 最多二十一次观测

1. **重复测量六次**：10 QPS，A/B 交错，各三个预声明种子 42/43/44。
2. **增压六次**：100、500、1000 QPS 逐级增加，每级各 A/B 一次。某组成出现无效观测或 P95 超过 1000 ms，停止该组成更高强度的探测，不自动加线程或队列。
3. **敏感性筛查九次**：选 B 组成中最高的有效且排队 P95 不高于服务 P95 的到达率；没有符合条件的强度则停止。固定配置序列为“基准、候选、基准、候选、……、基准”，四个候选次序用种子 20261124 固定。每个候选只改一项：
   - 缓冲池 2 GiB；
   - I/O capacity 1600；
   - I/O capacity max 6000；
   - 排序缓冲区 8 MiB。

候选都相对于启动时的完整配置，其他参数不变；若候选越界或不构成单参数变化，实验开始前拒绝。敏感性部分只做一个筛查块，不以单次效果宣称显著性。不能将其结果直接当作 GP 调参训练集或正式测试集。

正常请求流合计约 29.4 分钟，另有应用、检查和导出开销。最多 21 次测量，活动超过 2100 秒不再启动新测量。该门槛不是强制杀线程的硬实时截止；安全排空和恢复仍须完成。LLM 调用及 token 预算均为零。

## 安全与审计

- 与动态调优复用同一配置路径文件锁，禁止并发修改实例。
- 应用前后检查缓冲池后台调整空闲及容量；逐次备份、回读并核对持久性和隔离等不变量。
- 每个试验在线程池完全退出后关闭其连接，再开始下一次配置变更，避免累积空闲连接或跨配置请求。
- 最终恢复启动时配置文件与运行参数，等待 resize 完成并保存 SHA256；失败也执行恢复。
- 保存估计的表/索引字节数、精确行范围预检、完整配置、计划、逐请求/窗口 JSONL 和 CSV。
- 数据库计数增量、MySQL 进程 CPU 核当量及进程 I/O 覆盖整个 84 秒流及排空开销，**不是单独 60 秒测量窗口的精确归因**。不使用宿主机共享磁盘总计数冒充数据库独占 I/O。
- 最高有效到达率不等于数据库饱和点；固定四线程可能先限制客户端。有限三个重复也不足以精确估计噪声分布。

## 命令

```sh
python -m admtune.calibration \
  --target configs/local/autodl-smoke-target.yaml \
  --benchmark configs/local/autodl-smoke-benchmark.yaml \
  --knobs configs/local/autodl-smoke-knobs.yaml \
  --dedicated-instance \
  --output runs/autodl-calibration-20261124-001
```

`progress.json` 记录当前试验；逐次结论追加到 `trials.jsonl`；结束写入 `summary.json`。凭证、配置备份和运行产物不提交 Git，中文结论另行记录并提交。
