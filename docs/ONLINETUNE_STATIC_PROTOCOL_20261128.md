# OnlineTune静态适配：同实例增补协议

## 范围

本次只补现有Sysbench事务五方法图，不重跑已有四方法，不将静态结果当作OnlineTune动态编码/聚类的验收。显示名为 **OnlineTune (static adapter)**，算法键为`OnlineTune`。

使用同一实例`autodl-container-77c34b852e-98bb92e3`，参照`/root/experiment-results/static-quick-20261127`。代码强制核对实例、数据完整校验和、初始配置、负载、参数目录及共同预算。旧四方法原件保持不变。

## 共同条件

- MySQL8.0.36，四表各200万行，3308、同一数据；每次恢复同一初始配置。
- 原生Sysbench只读事务，32线程、uniform、seed42、15秒预热＋60秒测量。
- 仍最大化同次TPS/P95，另报告原始TPS和P95。不是单目标TPS优化。
- 最多8条真实观测，包含初始、至多6次建议和最终独立复测；活动时间1500秒。相同上限，不补偿失败槽位，不自动重跑。
- OnlineTune不调用LLM；不导入已有其他方法的性能标签或最优配置。参考四方法文件只用于环境/协议核对和绘图。
- 预算与模型中真实记录、原类初始化dummy点、重复配置分别报告，不把GP内部行数当真实试验次数。

## 实际执行的原核心

固定上游`88ba8c35f554bc4a4f7f1a88257b3e8928f87a39`。原件及补丁后文件在私有目录，不直接复制进公开仓库。适配器逐文件校验固定SHA256，生成补丁清单。

实际导入原`SafetyMixin`、`SubDomainBO/AscentLineBO`、`GP`、`TrustRegionDomain/LineDomain`：保留Matérn52＋上下文线性核、目标和约束GP、安全置信界、自适应beta、信赖域/线搜索切换及安全扩张器。未改为ADMTune的代理模型。

兼容补丁：多余括号、旧命名空间、核参数拼写、NumPy旧标量接口、固定40参数切片改为实际维度、交互调试改为抛出异常。公共参数目录负责整数步长、特殊值与硬约束，动作坐标沿用上游线性映射。

## 与完整动态原实现的差别

1. 当前是固定事务负载，只使用单一静态区域和常量10维上下文；不加载SQL编码器，不宣称运行了DBSCAN/SVM动态区域选择。
2. 缺失的`tune.model`不伪造：以本次预算内真实初始测量作为静态默认性能基准，不使用离线训练标签。
3. 不提供缺失的fANOVA历史；请求重要性方向时使用原源码已定义的随机方向后备。替换原40参数DBA规则为共同目录硬约束，不让规则改动目录外或持久性参数。
4. 使用四方法统一的测量、回读、恢复、记录接口；不运行上游压测/清连接脚本。

因此本轮结果是原安全搜索核心的**静态、冷启动、统一执行器适配**，不是完整OnlineTune动态论文复现。若静态下保守地回到已知配置，原样测量和留档，不偷偷换成随机搜索来制造更好曲线。

## 已完成的软件检查

独立Python3.10环境安装GPy1.13.2、NumPy1.26.4、SciPy1.12.0，不污染既有环境；无GPU或TensorFlow依赖。24步人工函数的软件验收实际经过`best`、`tr`、`line`，确认原核心能选点、接收反馈并切换子空间。人工结果仅在`onlinetune-software-check-001`私有目录，**不是数据库实测，也不进入论文曲线**。

常量、严格安全冷启动的软件验收出现保守中心重复，故正式小预算运行不保证新配置或性能收益。这是实验前已知限制，不因结果不好修改安全条件。
