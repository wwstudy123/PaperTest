# 综合指标与数据库并发探针协议

## 目标与历史隔离

新一轮评估预先固定为同次观测的 `TPS / P95(ms)`，越大越好，仍独立报告TPS、平均延迟和P95。它与前71次纯TPS优化目标不同；不得改写前71次优化目标、将旧记录标成综合目标调优，也不得把固定1000 TPS延迟与最大吞吐拼接。

本轮只做零LLM手工参数诊断，原执行适配器继续返回原始TPS，综合分数单独保存为 `joint_value`。还没有宣称已接通综合目标的付费搜索闭环。未来训练、经验库和基线若采用该目标，必须使用新的目标标识及完整测量协议。没有业务SLO，因此不凭空增加20%等硬阈值；综合指标也不是硬SLO保证。

## 预先固定的九次测量

| 配置 | 缓冲池 | innodb_thread_concurrency | io_capacity / max | sort_buffer_size |
|---|---:|---:|---:|---:|
| Default | 1 GiB | 0（不限制） | 200 / 2000 | 256 KiB |
| BufferOnly | 4 GiB | 0 | 200 / 2000 | 256 KiB |
| Concurrency8 | 4 GiB | 8 | 200 / 2000 | 256 KiB |

仅检查一个有资源依据的取值8：当前容器总CPU配额12核，前轮大缓冲池运行接近该配额，数据库与Sysbench客户端共同消耗CPU，假设数据库层限制并发可能留出余量。**这不是已知最优值，也不能保证8个InnoDB并发线程等于8核CPU使用。** 若无效，不能推断其他取值均无效。

官方MySQL 8.0文档说明该变量为动态全局变量，0表示不限制InnoDB并发线程；部署前另已只读确认实机8.0.36变量存在且为0。本轮只改数据库参数，不改OS配额、调度器或容器限制。

三位置平衡区组：

1. Default → BufferOnly → Concurrency8。
2. BufferOnly → Concurrency8 → Default。
3. Concurrency8 → Default → BufferOnly。

保持原生Sysbench只读、uniform、32客户端线程、种子42、15秒预热加60秒测量；恢复无请求速率限制。新工作树隔离部署，独立冷恢复一次，每次前后恢复完整初始配置并等待缓冲池扩缩容完成。

参数空间新增 `innodb_thread_concurrency`：显式0特殊值，普通取值1—32；本轮只执行0/8。保存完整五参数配置和新增参数的实际回读。记录 `innodb_thread_sleep_delay`、`innodb_adaptive_max_sleep_delay`、`innodb_concurrency_tickets` 的前后值，不额外调优它们；若运行时自适应产生变化，必须报告。每次前后及最终在恢复并发限制0之后，将这些上下文变量复位到本轮初始读值并回读校验，避免自适应睡眠状态悄悄带入下一次。

## 验证和解释

- 九次均保存正式测量边界的CPU、节流、进程I/O、InnoDB读取及原始日志；不使用宿主机全局指标代替本容器。
- 校验无 `--rate` 注入，正式日志没有固定事务率头；不把降低请求到达率混作数据库并发参数收益。
- 保存全部观测和同区组差值，不因结果不好而替换Default、删掉探针、追加其他取值直到获胜。
- 此参数可能通过排队、睡眠和事务票据影响延迟；即使节流降低也不能先验声称尾延迟必然改善。
- 比较组三次中位数以及每组的TPS/P95，不将独立TPS和P95中位数拼成单次最优观测。
- 原始数据与既有71次调优、9次无速率限制诊断、9次固定1000 TPS诊断分别保存，不混入旧GP训练集。
- 结束后恢复配置和新增变量0，复核配置文件SHA、耐久性、行数和逻辑样本哈希；LLM调用为0。
