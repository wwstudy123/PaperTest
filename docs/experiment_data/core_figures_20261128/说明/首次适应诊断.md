# ADMTune首次A阶段慢：原始证据与最小修复

本次只离线分析已完成的种子43，数据库和LLM新增调用均为0。旧数据、旧模型、旧负结果和曲线保留，不把修复收益当作已实测。

## 关键发现

| 项目 | 原始记录 |
|---|---:|
| A1冻结达标阈值 | P95≤59.7473 ms，连续三个20秒完整窗口 |
| 第一个达到该阈值的配置观测 | 58.3085 ms，192秒封存 |
| 连续服务实际达标 | 560秒 |
| A1的GP预筛事件 | **0** |
| A1失败配置观测 | **2** |
| 两次超时记录中的resize等待合计 | 119.88秒 |
| 从这两次失败试验发起到下一试验发起的区间合计 | 202.59秒 |
| A1选择＋裁剪＋推荐LLM调用耗时合计 | 17.65秒 |

202.59秒包含配置应用、回退、计算等，不能全部算作resize等待。第一个良好观测在192秒出现，也不等于连续服务在192秒已经达标：后续探索会再次扰动正在服务的配置。

原运行ADMTune实际占用14个试验槽，其中12个有效、2个执行失败。18000条业务请求全部成功与“没有配置观测失败”不是同一件事。新开销图将同时保存有效观测和包含失败的试验槽位，不能用12替代全部成本。

## 可复核的执行链

1. 候选池第一次围绕1 GiB父配置生成。
2. 2 GiB缓冲池候选测得58.3085 ms，被接受为当前父配置。
3. 后续仍取同一个旧绝对配置池，尝试1 GiB＋其他参数改动，反复撤销已经有效的缓冲池增长。
4. 两次缩容相关观测因60秒内未等到resize完成而失败；记录显示状态码3、配置值与页记账均为1 GiB。**页计数一致不构成后台调整已完成的充分证据，本次不放宽检查。**
5. 失败观测不进入GP训练。A1搜索期间有效样本不足bootstrap，未执行GP预筛；因此不能把首次A慢归因于GP误拒。
6. 最后恢复2 GiB做独立复测，三窗口服务达标在560秒才确认。

这是原始时间链所支持的原因分析；“修复后一定优于其他方法”仍需另测。

## 另外发现：反思通路不完整

原A2（旧A重现）选择、裁剪提示词含反思摘要，但候选推荐提示词只含一条measurement。原因是`PooledTeam.recommend`把`experiences`直接切成`[:1]`，截掉了排在数值记录后的文字经验。

原反思输入也缺少执行失败原因，只给出`constraints_ok=false`。生成的一个待验证解释将失败归因于“违反约束”，而原始原因实际是resize等待超时。结构/证据编号校验不能自动保证自然语言因果解释正确，不能把该假设写成观测事实。

## 本次最小代码修复（尚未重跑性能）

- 候选缓存键改为阶段、父配置及有效范围；这些发生变化时重建一次，同父配置/同范围仍复用候选以节省API。
- 选择、裁剪和推荐统一使用“一条数值记录＋一条有界反思摘要”，保留条件、证据ID和截断标记，不再让推荐端丢失所有反思。
- 假设预览显式标记未验证。
- 给失败反思补充完整性、有效性及已脱敏、有界的失败原因，并提示`constraints_ok=false`不等于证明硬参数约束被违反。
- 不改变resize完成判据、GP安全阈值、真实测量时长或失败记账，也不重置已用槽位。

所有修改属于新的ADMTune版本；当前运行的OnlineTune使用冻结旧工作树，不受本地修复影响。

## 下一步的有效性验证

先用单轮受控诊断检验父配置是否随接受更新、是否仍频繁回撤缓冲池、推荐提示是否包含反思以及A1服务达标时间。若依据种子43修改方法，应将该轮保留为开发先导，新版本冻结后再做独立重复，不把本轮修复过程混成预注册确认性结果。

随后优先无GP、无跨阶段历史消融；另用同一段记录做增量/全量反思离线重放，分清“文字反思”和“增量处理”的贡献。修复未实测前不急于投入整套付费消融。
