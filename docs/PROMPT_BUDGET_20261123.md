# 动态试运行的模型费用检查

## 本轮修正

`0.7.3` 在紧凑 JSON、阶段反馈清理及解释预览限长的基础上，对动态阶段末反思增加可逆编号编码：

- 传输时将本批原始试验编号映射为 `t1`、`t2` 等短编号，事实数值、状态、配置、阶段及条件不变。
- 返回后还原事实、证据列表及解释文本内的编号，再交给原有经验库校验。未知结构化编号直接失败，不补齐遗漏事实，也不修正模型改写的数字。
- 映射及解码响应保存到 `reflection_maps/`，接口原始提示和响应仍保存到 `llm_calls/`。可以对照原始全编号证据审计，不依赖模型记住映射。
- 本轮反思仍只处理新增记录、不附带旧摘要；编码器拒绝不支持的旧摘要输入，而非悄悄删除。
- 每个接口记录实际发送字节、最大输出、协议余量、保守预留及调用前剩余额度，账本继续按真实接口用量结算。未知用量保留全额预留；无隐式重试。

原始经验编号和事实不变，不改变 GP、候选准入、配置接受规则或测量时长。这不是新的搜索算法或独立创新点。

## 零费用检查

对上一轮已有十个提示进行当前规则的离线重新编码，总输入减少 5486 个 UTF-8 字节；网络和模型接口调用均为零。阶段三选择/裁剪的单次保守预留由 5630/5972 降至 4179/4518，两个已有反思提示由 4189/3846 降至 3681/3421。

这只是对已有提示的字节核算，不是分词器实测或新响应预测。不能将字节节省直接换算成相同数量的实际 token 节省，也不能保证十二次新调用一定完成。完整三阶段检查仍保留 **12 次请求、20000 token** 的硬上限，触发保护则如实失败，不加预算重试。

测试覆盖可逆编码、未知编号拒绝、原始输入不变、解释内引用还原、错误数值不被修补、原经验库拒绝失真事实、增量消费与不重复反思。

## 下一轮实机协议

沿用同一专用实例、四表各十万行、每秒十条请求、组成 A→B→A；每阶段 600 秒，预热 15 秒、观测 60 秒。新目录 `autodl-dynamic-llm-002`，不续写或覆写上次失败目录。

只启动一轮有界真实模型试运行，完成后校验配置恢复及逐请求、GP、用量和反思记录。仍是小规模控制流验收，不是正式基线或消融；未做数据快照复位，不与上一轮直接比较性能优劣。真实结果另行记录。
