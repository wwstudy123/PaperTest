# 综合目标搜索闭环小预算联调协议

本轮不再手工选择配置；使用真实LLM角色生成候选、真实GP预筛、实测接受/恢复及增量反思。不是新的100分钟正式矩阵。

## 1. 目标与标签

- 优化目标标识 `tps_per_p95:maximize`，必须使用同一次完整测量的TPS和事务P95（ms）。
- 原始Sysbench适配器仍解析TPS、P95；新评分适配器单独计算比值，规范标签保留6位小数。GP训练的是该规范标签的自然对数，候选LCB/UCB及实测接受均用相同目标。
- 保留完整精度比值、原始TPS和P95，不能把综合分数导出到TPS列。反思事实复制规范标签，不重新计算或修改事实值；数值复制错误仍拒绝提交。
- 6位小数是预先声明的数值序列化精度，不是修改实测TPS/P95，也不是通过四舍五入制造1%的接受收益。
- 未设业务硬SLO。LCB的10%综合分数容忍下降与1%最小接受收益不是P95上限，也不是性能安全的数学保证。原执行器P95≤1000 ms运行保护保持不变。
- 联合Matérn-5/2 GP、完整配置编码、静态常量上下文；不能写成已验证动态上下文核或完整动态创新。

## 2. 实测和费用上限

- 专用MySQL 8.0.36、3308、四表各200万行；原生只读、uniform、32线程、种子42、15秒预热+60秒正式测量，无请求速率限制。
- 完整五参数空间与并发探针相同，保留并发参数0特殊值；最多选择4个参数、每批最多8个候选。没有将并发8固定为推荐结果。
- 最多8次真实测量，包含初始基线和最后独立复测；最多20分钟活动预算。
- 最多8次实际API尝试、32000 tokens（含失败未知用量预留），使用已配置的qwen3.7-plus。未知失败不退还预留，不启用启发式降级。
- 为末端反思保留1次调用、10000 tokens的请求前预算空间及30秒估计时间；这些是预留上限，不是实际支出。最终复测和恢复也预留在本轮预算内。
- GP至少6条有效观测才拟合；最后必须独立复测推荐父配置，并在预算内做一次阶段结束增量反思。
- 如果角色格式错误，至多一次显式记账的格式纠错，硬约束不放宽；若预算不足或验证仍失败，保留失败并停止。

## 3. 取消无意义重复

旧协议可能在没有可试验候选时不断测已有最优配置；新协议不再生成这类 `incumbent_repeat`。

1. 空候选池不因旧seq+8冷却而直接重复旧配置；允许生成新批次。
2. 候选经过GP后全部不满足当前LCB/UCB条件，记录模型版本、拒绝配置以及“未执行”语义，清空该池。
3. 当前决策最多刷新一次，整个运行最多触发两次这类刷新；同模型版本已拒绝的配置不重复进入刷新池。
4. 刷新后仍没有新颖、可试验候选，明确提前停止；不把候选拒绝写成真实测量，也不占用虚假测量编号。
5. 停止时使用已预留预算独立复测当前接受配置。提前停止不等于证明全局最优。

固定的每5号抽样审计仍可绕过代理性能预筛，用于探索与检查，但不绕过完整配置/硬约束验证。它单独标记为 `audit`，不能冒充GP筛选的新候选。独立末端复测也不算违规重复。

## 4. 历史和物理状态隔离

- 新环境/协议标识包含目标、标签精度、参数空间、策略及预算；禁止从其他目标或环境的账本训练GP。
- 新账本不导入旧71次、手工并发探针或固定1000 TPS观测。旧工作树与原记录保持冻结，不把新目标接到原72号。
- 本轮开始前独立冷恢复；每次测量结束恢复共同初始配置。已接受的配置作为下一批候选的逻辑父配置，并非声明数据库一直部署在该配置。
- 若并发参数触发自适应sleep_delay变化，完整恢复到初始并发上下文再开始下一次；保存实际边界CPU、节流、读取和上下文证据。
- 不更改CPU配额、不降低持久性、不关闭观测能力、不修改查询语义。

## 5. 验收与未证明内容

必须逐项核验：真实日志和规范分数对应、GP标签为log(同次比值)、预测训练ID严格早于测试观测、目标一致的候选排序与接受、真实角色用量、增量反思事实及证据、无填充重复、最终配置和数据状态恢复。

`closed_loop_verified`还要求GP参与至少一次候选筛选/拒绝决策，而不是只有对最后复测的预测。反思事实错误不自动修复或伪造成功；字段记录失败原因。

小预算联调可能提前停止、没有新最优，甚至不足以建立GP；均按实际结果报告。不能用它代替六方法、三种子、动态场景和消融的正式结论。

入口：`python -m admtune.composite_static`，需要五参数本地配置、独立冷恢复审计以及 `--dedicated-instance --allow-paid-llm`。输出必须是新的目录。
