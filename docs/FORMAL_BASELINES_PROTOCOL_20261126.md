# 正式数据库层基线协议 v1

## 1. 比较对象与来源

| 方法 | 必须保留的机制 | 本次适配 |
|---|---|---|
| Default | 原始配置，不搜索 | 独立压测三次，零 LLM |
| AgenticDB（DB-only） | LLM 全局配置规划、逐轮执行反馈记忆、规则 Auditor、成功接受与失败恢复 | 按用户要求删除 OS 阶段；平台后停止，不转 OS |
| AgentTune | 规则负载特征、匿名旋钮选择、范围／步长／特殊值裁剪、束搜索、质心距离排名、top-5 实测记忆 | 在共同五参数目录选四项；k=2、每父节点 R=3；结构化 JSON 和共同执行器 |
| ADMTune | 现有多智能体、上下文 GP、增量反思 | 必须在此协议重新实测，不能把旧协议曲线拼入新比较 |

源版本和文件 SHA256 见 `experiment_data/formal_baseline_sources_20261126.json`。AgentTune 原版提交为 `9b68872434665ef552b98999b05a785cb5d7aa4c`，AgenticDB 为 `321cb7ca350bbf382e7a1696ccfff859ac53f315`。复现版仅辅助审阅，不取代原算法。

这是**论文算法的共同执行环境适配实现**，不是声称原工程未经修改即可运行。原 AgentTune 存在初始化变量、配置类型及路径依赖问题；这里只移植机制，不执行其任意 shell，不复用其把 QPS 除以 20 的写负载假设。原版未发现许可文件，未把原代码加入公开仓库；质心排名使用独立实现，并以隔离执行原纯函数得到的 24 组固定向量检验，保留原版 competition rank（并列 1、1、3，而非 1、1、2）。

## 2. 完全共同的条件

- MySQL 8.0.36，专用端口 3308，四表、每表 200 万行；数据规模不再使用旧的约 98 MiB 小样本。
- Sysbench 原生 `oltp_read_only.lua`，32 线程，均匀访问，seed=42，预热 15 秒、测量 60 秒；不修改负载增强单个方法。
- 相同五参数硬目录、资源约束、初始配置、应用回读、缓冲池 resize 等待和失败恢复。不放松持久性语义。
- 统一最大化同一次测量的 `TPS / P95(ms)`，保存未经修改的 TPS 和 P95；性能表分别报告 TPS、P95 和组合效用，不能把组合效用写成 TPS。
- 各方法都从空的跨任务历史开始；运行内反馈记忆属于方法本身，予以保留。
- 相同实际 API 模型与端点，密钥仅在服务器忽略文件中。AgentTune 的推荐温度 1、top_p=0.98，选择和裁剪温度 0；AgenticDB 规划温度 0.2。这是方法配置，不强行统一温度。
- LLM 提供方不提供已验证的 seed 控制，重复编号不是“确定性模型随机种子”。

## 3. 预算与停止

每个调优方法最多 **8 次真实测量（初始 1、搜索至多 6、独立最终复测 1）**、**1500 秒活动时长**、**20 次 API 尝试**、**64000 token**。失败测量不退款；API 失败且无 usage 时保留预扣；禁止缓存 AgentTune 的同提示独立子节点调用。

AgentTune 满束时三层搜索需要 3+6+6 次推荐，加选择、裁剪共 17 次；初始化最多一次有记录的格式修正，子节点非法则拒绝，不偷偷补采样。其他调用错误不隐式重试。AgenticDB 按原规则可提前停止，不为凑八次而编造候选。Default 预先固定三次实测，不补齐搜索预算。最终复测占用预算，不能用搜索极值替代最终性能。三个连续无效测量停止搜索并进入恢复／最终验证。

ADMTune 使用 repeat-aware GP，此短预算协议不额外占用三次初始噪声重复；若数据不足以估计重复噪声，报告未激活，不能宣称已有可靠噪声估计。

## 4. 每种方法前后的数据校验与冷启动

为避免磁盘不足反复复制约 3.86 GB 的数据目录，本协议对**只读**负载采用：

1. 检查配置文件哈希、实例身份、行数／主键范围、固定样本以及全部四表 `CHECKSUM TABLE ... EXTENDED`。首次登记完整校验和，后续必须相同。
2. 正常关闭 MySQL；独立启动，显式关闭 buffer-pool dump/load，重置 InnoDB 缓存。不删除旧数据、快照、PID 或结果。
3. 不清空操作系统页缓存，所有方法执行同一规则；不能称为整机全冷缓存。
4. 方法结束恢复初始参数，再核验完整数据校验和。任何失败立即停批次，保留日志，不自动重跑收费。

此协议区别于过去的物理副本重置，**旧 ADMTune／消融曲线不能与新结果作同条件比较**。

## 5. 实现和运行

入口：`admtune.formal_baselines`；本地算法：`admtune.baseline_strategies`；重置工具：`tools.reset_readonly_baseline`；串行批次：`tools.run_formal_baseline_batch`。

服务器准备同一 Python 环境、已有三份私有 YAML 与 `.env` 后：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
python -m tools.run_formal_baseline_batch \
  --output /root/autodl-tmp/formal-baselines-repeat0 \
  --repeat 0 --methods Default AgenticDB AgentTune \
  --dedicated-instance --allow-paid-llm
```

输出逐次 SQLite 事务账本、JSONL、CSV、算法状态、全部收费调用的输入输出及 usage、运行前后校验、摘要和文件哈希。真实数据原件私有留存，公开绘图包只导出脱敏数值和可追溯试验编号。

## 6. 绘图与正式结论边界

首轮可产出三方法的真实性能表及曲线；若 ADMTune 尚未按相同协议重跑，不把旧 ADMTune 加入该图。每方法至少补三次独立重复、轮换顺序，再给均值、离散程度和效应比较。固定负载整体性能不能替代动态负载适应、历史复用、GP 校准及反思消融。

GPTuner、CDBTune 尚不因新增此入口自动成为正式基线，必须另行接入原方法并同条件测量。不得把启发式、GP-off 或文献数值改名当作这些方法。
