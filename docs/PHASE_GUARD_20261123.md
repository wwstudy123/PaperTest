# 2026-11-23 阶段时长与跨阶段观测保护验收

## 修复了什么

问题不是此前动态监测失败，而是监测烟测和参数试验的协议不兼容：24 秒阶段扣除约 16 秒稳定确认，只剩 8 秒，不能放下 15 秒预热加 60 秒测量，更不包含应用与恢复。

本轮没有缩短测量，也没有把不同工作负载的指标拼接起来。新增实际 benchmark 驱动的阶段预算规划、阶段级准入、持续窗口栅栏及执行器装饰器；疑似变化即拒绝在途观测，完整覆盖窗口到达前不交付测量标签。

完整设计和限制见 [阶段安全机制](PHASE_SAFETY.md)。同步静态控制器没有被宣称已经改造成完整动态优化器：装饰器需要在独立调优线程运行，本轮实机验证的是持续回放上的观测栅栏，装饰器与现有 trainable 条件的衔接由单元测试验证。

第 8 秒初始阶段就绪，保留第 8–23 秒预热区间、第 23–83 秒测量区间；测量区间包含 600 条成功请求。第 84 秒完整窗口到达后封存，确认所有请求都已在封存前完成，期间没有跨越公告切换边界。

### 2. 阶段尾部不能盲目启动长观测

第 92 秒距第 96 秒公告边界只剩 4 秒。正常观测仍需保留 15+60 秒及封存预算，因此被明确拒绝，未为此额外发出压测请求。拒绝理由为剩余阶段时间不足，不借用下一阶段时间。

### 3. 故意跨阶段的观测必须失效

只在验收模式下明确绕过准入，建立第 92–100 秒的故意探针，覆盖第 96 秒的 A→B 切换，包含 80 条真实请求。第 100 秒窗口报告变化怀疑时，栅栏将其拒绝：

```text
status = rejected
reason = workload_change_or_unstable
accepted_observation = false
value = null
gp_label_written = false
```

这不是因为请求执行失败而拒绝：80 条请求本身全部成功，失效原因是上下文跨阶段。验收程序还用公告边界进行独立事后核查，确认确实跨段。

## 结论与边界

阶段时长不兼容现在能够在运行前被拒绝；同阶段观测与故意跨阶段观测的不同处理已通过受控实机验收。不再以“把测量缩到几秒”作为解决办法。

这不等于完整动态参数闭环完成，也不证明未知线上负载永不漏检。有限窗口无法证明未观察到的物理变化不存在；本轮公告边界、运行时栅栏与事后审计各自独立记录，没有把未来 A/B 标签喂给检测器。

下一步是在相同负载协议下实现真正的动态性能执行器和独立调优线程，再进行基准重测、参数搜索与受控恢复；不能并行注入静态 Sysbench，把低速单 SQL 回放冒充高吞吐优化实验。
