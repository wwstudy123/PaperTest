# 四方法动态主实验与消融：冻结协议 v1

## 研究顺序

保留阶段1所有冷态失败、暖态补测和动态先导，不把它们计入正式重复。正式请求种子43、44、45；先跑43完成四方法首轮并检查实现，再补44、45。先导通过只说明值得继续，不保证ADMTune优于其他方法。

## 统一实验

- 专用MySQL 8.0.36、3308、四表各200万行、CPU配额12核、90 GiB内存；四个数据库参数共同硬目录，不探索OS。
- 初始缓冲池1 GiB、排序缓冲256 KiB、I/O capacity 200/max 2000、并发限制0；只读数据完整校验后独立启动，关闭缓冲池dump/load。不清空OS页缓存。
- 每方法固定180秒中性只读预热，预热请求种子1000+正式种子；不在预热期间调优，也不输入模型。
- 正式30分钟A→B→A，各600秒；扫描/排序比例9:1→1:9→9:1；外生10 QPS、4工作线程、R32768/K8192，同一配对种子使用完全相同SQL请求轨迹。
- 每个调优方法上限18个真实配置观测、36次真实API、100000 token；15秒预热＋60秒观测。失败不退款，未用完不凑数。Default持续服务30分钟、零API，不机械凑18个配置观测。
- 共同模型和端点；提供方LLM seed不可控。配对种子控制请求轨迹及本地随机源，不称为确定性LLM种子。
- 每个独立运行创建空Store；只允许本次A阶段产生的事实和经验在本次后续阶段复用。校准仅提供固定0.02对数尺度观测噪声，不导入性能标签或已知最优配置。

## 方法实现与动态适配

| 方法 | 保留机制 | 动态适配 |
|---|---|---|
| Default | 初始配置 | 全程不调优 |
| AgenticDB-DB-only | 全局规划、执行反馈、规则Auditor、1%收益接受 | 共享当前负载变化触发；每阶段重新开始搜索与Auditor，保留实际运行配置及本次已测事实 |
| AgentTune | 匿名选择、裁剪、R=3独立推荐、k=2质心排名、top-5实测记忆 | 共享变化触发；每阶段从当前基准重新初始化束，保留本次实测记忆；不加GP或Reflexion |
| ADMTune | 多时间片上下文、LLM分工、历史检索、GP预筛、增量文字反思 | 每阶段批量候选、逐观测更新GP、阶段末批量反思，保持当前已接受配置持续服务 |

基线明确为原方法搜索机制的共同执行环境/动态目标适配，不是声称未修改的原工程支持本负载。内部排序分数为1/P95，原始记录始终保存P95毫秒，不伪装为TPS。AgentTune选择/裁剪温度0、推荐温度1/top_p=.98；AgenticDB与ADMTune沿用客户端0.2。正式单次最大输出统一1500 token，为全局规划JSON提供空间；未使用的输出额度不凑数。AgentTune独立子节点不缓存答案。

共享变化触发是为避免把基线“调一次后冻结”并隔离搜索/代理/经验部分的差异。因此不能用该四方法比较宣称检测器优于其他方法；多时间片的增量作用由其消融另测。物理执行器按各方法的接受规则保留实测最优配置，拒绝候选恢复已接受配置，不每次恢复全局默认值。

AgenticDB跨阶段保留原生规划/执行反馈记录，Auditor只按当前工作负载阶段判断平台期；不是删除其文字计划后再与ADMTune比较。AgentTune保留本次运行的top-5实测记忆，但新阶段束的起点必须是该阶段真实基准，而不是全程第一条旧基准。

## 指标

1. **全过程端到端P95**：20秒发出请求cohort，以及完整阶段/完整运行的原始请求分位数，包含试验、配置切换和推理期间服务表现。
2. **累计成功完成请求数**：按真实完成时间累计。固定到达率下曲线可能重合，不人为拉开。
3. **阶段适应耗时**：首次确认连续3个完整20秒窗口的P95均不超过该配对种子Default对应阶段“窗口P95中位数”的90%；从阶段起点到第三个窗口结束计时。阈值只用于离线统一评价，不输入推荐器或检测器。未达标记NA，不填0；同时报告达标次数，不能删NA后只比条件均值。

辅助表：失败、超时、丢弃、观测状态、调用/token和阶段检测时刻。累计请求响应时间作为补充，不替代上述三项。先导的适应规则为事后探索评分，正式从本协议起固定，不回填其确认性身份。

## 消融预置开关

- `single_slice`：单时间片编码，SQL和到达计划完全不变。
- `no_history`：禁止跨阶段事实/文字检索，阶段开始清空GP状态；保留正在服务的配置，不能通过恢复默认人为削弱它。
- `no_gp`：保留相同LLM候选与真实执行，不使用代理预筛。
- `no_reflection`：禁止文字反思生成和读取，保留实测事实与GP。

这些开关在正式full运行前已实现；后续消融使用同一源码、同一请求种子、共同资源上限。完整ADMTune结果直接复用正式full，不重新跑一组。任何开关实测失败都保留并先检查，不能仅重复有利消融。

## 执行与停止

入口`tools.run_dynamic_matrix --seeds 43`默认只跑首轮；方法顺序随种子轮换。每运行保存冻结源码、参数配置哈希、请求轨迹、接口原件和完整测量记录。运行失败立即停矩阵、保留原件，不自动付费重跑。

如果发现工程或协议错误，修正后重新冻结，旧数据单列；如果闭环正常但没有优势，不把它当工程错误来挑种子重跑。三次独立重复用于呈现一致性和离散程度，不自动意味着统计显著。OnlineTune适配与TPC-H另立阶段，不以自写GP或论文比例曲线替代实测方法。
