# OnlineTune动态接入：冻结接口与验收顺序

## 本次改动

本次优先完善动态流程，暂停静态OnlineTune数据库试验。不修改已完成四方法的原始结果，不把静态常量上下文曲线放入动态图。

动态适配已加入：

1. 从已经封闭的4秒到达窗口提取10维SQL结构/访问/请求强度特征。禁止读取请求的A/B标签、未来窗口、实测延迟或配置作为负载特征。
2. 在过去窗口上拟合StandardScaler、PCA（至多3维）、DBSCAN（eps0.7/min_samples8）和RBF SVM（gamma=auto）。临时聚类编号映射为稳定区域编号；新负载窗口不足8个时建立临时区域，不强行放入旧模型。
3. 每区域使用原OnlineTune的SafetyMixin、目标/约束GP、信赖域与线搜索，不用ADMTune的GP。
4. A重现时取回旧区域、观测和GP超参数，重表达为当前已实测阶段基准下的目标差值/相对约束，而不是重建空模型。
5. 按上游“相对收益>10%且高于已观测90分位数”规则，将高收益观测迁移到其他区域的目标模型。迁移不是其他区域的新安全测量，不能写入其约束模型。
6. 阶段基准、候选、复测均来自同一持续请求流；共用阶段栅栏、18条观测上限、恢复和零LLM记录。

## 与原论文编码器的区别

动态链路不再使用常量上下文。但原仓库缺失词表及`gen_context`等资产，当前使用因果可观测SQL结构特征，而不是声称还原了原LSTM词向量。原40参数DBA规则替换为共同硬目录；重要性方向仍使用原代码允许的随机后备。这些适配差异随运行清单记录，方法显示名应说明为动态适配版。

## 上下文与标签的边界

- 算法路由不读取A/B阶段名字、顺序、未来变更时刻；阶段栅栏仅用于共用的观测有效性保护。
- 分区域事实保存真实效用、配置、上下文、试验ID和来源区域；基准变化时重新中心化，不把旧阶段残差直接当成当前残差。
- 跨区迁移仅使用已经实际测完的记录，不把迁移记录计成额外数据库试验。
- 模型中的原始dummy点、实际观测与重复配置分开报告。
- 各次候选的均值、标准差及安全模型预测在测量前留档，不回填实测结果。

## 已完成的离线检查

- 原动态首轮逐请求到达记录的因果重放已识别区域`0→1→0`，实际使用SVM；只验证上下文和路由，不是OnlineTune性能。
- 独立环境的原GP动态软件验收已走完A→B→A，使用人工函数验证分区、模型保留和再中心化；人工标签不进入科研性能曲线。
- 记录位于`experiment_data/onlinetune_dynamic_checks_20261128/`及服务器私有软件验收目录。

## 实机步骤

1. 短时链路验收：每阶段160秒，0秒预热＋1秒测量，总服务8分钟；明确标记smoke。用来查观测栅栏、真实SQL、区域复用及恢复，不评估最终性能。
2. 通过后正式运行：同种子43、同四参数目录、180秒中性预热、30分钟A→B→A、每次15＋60秒、最多18条真实观测，LLM调用为0。不因保守拒绝而放松安全条件。
3. 异常停止并保存原件，不自动付费重跑；静态试验未再启动。

入口：

```bash
python -m tools.run_onlinetune_dynamic \
  --output <新的结果目录> --upstream <固定上游目录> \
  --dedicated-instance --smoke
```

去掉`--smoke`才是正式时长。短时链路结果不能直接加入正式性能折线图。
